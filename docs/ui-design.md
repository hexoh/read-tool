| 项 | 内容 |
| --- | --- |
| 版本 | v1.0 |

| 设计工具 | Figma（可用，见 §8 的四条限制） |

---

## 1. 先说结论：Figma 可以，但有四个坑

**能用，而且是首选。** 组件化、Variants、Dev Mode 标注、Prototype 演示，正好对得上我们这个项目"组件多、状态多、要给开发精确规格"的特点。

但以下四件事 Figma 做不好，必须提前定好绕行方案：

| 坑 | 具体表现 | 绕行方案 |
| --- | --- | --- |
| **竖排中文无原生支持** | Figma 没有 vertical writing mode，画竖排经文只能手动逐字换行 | 结果页的"原文区"直接用**真实书页截图**（降采样到 1000px 宽）代替模拟文本 |
| **生僻字显示豆腐** | 耨、槃、苾、蒭 在 Figma 网页端常缺字 | 把思源宋体子集上传为团队字体；关键文案在稿子旁附文字清单 |
| **环形依赖：字框画不对** | 500 个字框是运行时数据，静态稿画不出真实分布 | 稿子里只画 3–5 个框做**样式示意**，位置与密度写在规格里，由开发调试 |
| **动态行为稿子表达不了** | 浮层避让、朗读高亮跟随、坐标逆变换 | 静态稿 + **文字规格 + Prototype 演示**三件套，缺一开发就会做错 |

**一句话建议**：Figma 用来定「长相与状态」，动态行为用文字写死。别指望开发从图里"看出来"。

## 2. 信息架构

```
首页
├─ 拍照识字（主按钮）
├─ 相册导入
├─ 我的生字本
└─ 历史记录

相机页 ─→ 处理中 ─→ 结果页（核心）
                      ├─ 字卡（浮层，非独立页）
                      ├─ 简繁三视图切换
                      ├─ 读音模式切换
                      └─ 朗读模式（结果页的子状态）

设置页
├─ 默认读音（旧读 / 今读）
├─ 注音 / 拼音
├─ 语速
├─ 离线资源管理
└─ 隐私与关于
```

**只有 5 个主屏**：首页、相机、结果页、生字本、设置。字卡是浮层不是页——这点很重要，做成独立页会让"点字-看-返回"多两次跳转，破坏即时感。

## 3. 核心界面规格

### 3.1 结果页（最重要的一屏）

**垂直分区（高度比例）**

| 区域 | 占比 | 内容 |
| --- | --- | --- |
| 顶部栏 | 7% | 返回、页码/来源、"···" |
| 判定状态条 | 6% | 仅在 scripture / uncertain 时出现 |
| 原文区 | 45% | 原图 + 字框叠加 + 缩放拖动 |
| 工具条 | 7% | 三视图 / 注音拼音 / 朗读 |
| 字卡浮层 | 35% | 选中字的详情（可收起） |

**四条必须遵守的规则**

1. **默认显示的是原图，不是处理后的图。**
   字框坐标是在矫正后的图上算出来的，必须**逆变换回原图坐标系**再叠加——否则框会偏。这也是 B-03「不改原文」的界面落地：用户看到的永远是他拍的那张纸。

2. **选中色不能用朱砂红。**
   书页本身满是朱批、圈点、印章，红色框会与之混淆，用户分不清哪个是自己的选中。**统一用靛青 `#185FA5`**。

3. **字框线宽 1 物理像素（hairline），不随缩放加粗。**
   框是用来"定位"的，不是用来"装饰"的。选中框 2px + 10% 同色底，其余框降到 30% 不透明度。

4. **点字热区不是放大字框。**
   字框只有 24dp，达不到 48dp 触控标准，但放大框会导致相邻框重叠、点错字。正确做法：**保持视觉框原尺寸，命中算法取"点击点最近的框中心"**（阈值 32dp），而不是按矩形包含判定。

**字框的三种视觉态**

| 态 | 样式 | 用途 |
| --- | --- | --- |
| 默认 | 0.5px 暖灰 `rgba(120,110,90,0.3)`，无底色 | 正文 |
| 注文 | 同色 **虚线**，字号区域更小，可整块隐藏 | 双行夹注 |
| 选中 | 2px 靛青 + 10% 靛青底 + 其余框降至 30% | 当前字 |

### 3.2 字卡

结构（自下而上）：

```
把手条（可上滑展开 / 下滑收起）
├─ 主字（38–44sp 宋体）      ├─ 读音区
│                            │   bō rě        ← 15sp 靛青，主读音
│                            │   bān ruò      ← 12sp 灰，次读音
│                            │   ㄅㄛ ㄖㄜˇ    ← 注音（可切换）
├─ 元信息：部首 · 笔画 · Unicode（11sp 灰）
├─ 来源：般若 · 梵 prajñā（11sp，可选）
└─ 操作：[加入生字本] [纠正读音]
```

**双音排版采用"上下堆叠"（方案 A）**：旧读在上、主色加粗；今读在下、降一级灰度。理由：占位 44px 最平衡，注音再长也不换行，且主次靠**位置 + 颜色双重编码**，比纯颜色更可靠（色弱用户也能分辨）。

**浮层避让规则（必须写进实现）**

| 被点字的位置 | 字卡形态 |
| --- | --- |
| 原文区上半部 | 底部抽屉（默认） |
| 原文区下半部（会被抽屉遮挡） | **改为顶部抽屉**，从顶部滑下，箭头指向该字 |
| 靠近左/右边缘 | 抽屉不变，但原文区自动平移，让选中字居中可见 |

这条不做，用户体验就是"点一下，字被挡住了，还得手动拖"。

### 3.3 相机页

- **取景框用四角框线，不用完整矩形**——完整矩形压迫感强，且暗示"必须完全框内"。
- 提示语一行，13sp，居中在上方：`把文字放进框内，尽量正对、避免反光`
- 底部模式 chips：`自动 / 简体 / 繁体刻本 / 手写`（chips 而非 tab，因为这是"调节"不是"切换页面"）
- 快门：72dp 圆形，白色描边，下方无文字（图标自明）
- 左侧相册入口（48dp 缩略图），右侧闪光灯

**失败态三种，文案必须具体**

| 情况 | 文案 | 操作 |
| --- | --- | --- |
| 没找到文字 | 没找到文字，试试对焦或换个角度 | 重拍 / 手动框选 |
| 太模糊 | 照片不够清晰，可能影响识别 | 重拍 / 继续 |
| 光照过强（反光） | 有反光，稍微侧一点会更好 | 重拍 / 继续 |

### 3.4 首页

**不做信息流、不做推荐、不做"每日一字"**。一个大按钮 + 三个小入口：

```
┌─────────────────────┐
│                     │
│   [ 大按钮：拍照识字 ]  │  ← 56% 高度处，视觉中心
│                     │
│   [相册]  [生字本]  [历史] │
└─────────────────────┘
```

理由：主力用户（中老年、信众）打开 App 的目的极明确——拍一页、认字。任何引导流都会增加路径长度。

### 3.5 生字本

卡片流，每条包含：**原图裁剪片段**（80×80，保留纸感）+ 字 + 读音 + 来源页。裁剪片段是关键，用户靠"这张纸的样子"回忆，而不是靠字本身。

## 4. 视觉系统

### 4.1 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面底 | `#FAF8F4` | 极浅暖白，不用纯白（长看刺眼） |
| 卡片面 | `#FFFFFF` | — |
| 纸色（仅图片衬底） | `#F6F1E4` | **只用于原图外框，不做页面背景** |
| 主色（选中/旧读/主操作） | `#185FA5` | 靛青。避开红，见 §3.1 |
| 主色浅底 | `#E6F1FB` | 状态条背景 |
| 文字主 | `#2C2C2A` | 不用纯黑 |
| 文字次 | `#5F5E5A` | — |
| 文字弱 | `#8C8778` | 时间、页码 |
| 分隔线 | `#E3DAC6` | 暖灰，与纸色同族 |
| 警示（低置信/无音） | `#BA7517` | 琥珀，不用红——红色已属于"选中"的语义区 |

**暗色模式**：页面底 `#16161A`，纸色区域**保持不变**（因为那是图片内容，不能反转）。这条要提前跟开发说，否则暗色模式会被做成"整页反色"，图片变得不可读。

### 4.2 字体

| 用途 | 字体 | 字号 |
| --- | --- | --- |
| 原文/字形展示 | 思源宋体（子集，含 CJK Ext B） | 按图片缩放 |
| 字卡主字 | 思源宋体 | 38–44sp |
| UI 标题 | 思源黑体 Medium | 15–17sp |
| 正文 | 思源黑体 Regular | 13sp |
| 辅助信息 | 思源黑体 Regular | 11sp |
| 拼音/注音 | 思源黑体 + 等宽数字 | 12–15sp |

**注音的两个技术细节**（容易翻车）：

1. 注音符号（ㄅㄆㄇ）的基线与汉字不同，需单独设 `lineHeight`，否则与拼音混排时上下飘。
2. 需验证思源黑体是否覆盖全部注音符号与声调符号（ˊˇˋ˙），缺字要补字体或换字体。

### 4.3 间距与圆角

- 间距基数 4dp：4 / 8 / 12 / 16 / 24 / 32
- 圆角：卡片 12dp，chip 全圆，字框 3dp，按钮 8dp
- 字卡内部左右留白 16dp（比常见的 12dp 宽，因为要放注音，挤了会换行）

## 5. 组件与状态矩阵

| 组件 | 状态 | 备注 |
| --- | --- | --- |
| 字框 | 默认 / 注文 / 选中 / 低置信 / 无音 | 低置信用琥珀色细框 + 右上角小点，**不显示置信度数字** |
| 字卡 | 收起 / 展开 / 多音字展开 / 无音 / 加载中 | 无音时读音区显示拼音 + "暂无语音" |
| 判别状态条 | 经文 / 疑似 / 隐藏 | 普通文本时**不显示**，保持安静 |
| 工具条 | 三视图（3 态）/ 注音拼音（2 态）/ 朗读（播放/暂停） | — |
| 朗读高亮 | 当前字 / 已读 / 未读 | 当前字轻微放大 1.05 + 底色，不做滚动动画（会晕） |
| 空态 | 生字本空 / 历史空 | 一句话 + 一个返回拍照的按钮 |

**关于置信度**：产品上决定"不显示百分比数字"。用户看不懂 0.87 意味着什么，只会焦虑。低置信统一表达为"把握不大，请核对"的黄条 + 字框上的琥珀小点。

## 6. 关键动态行为（文字规格，必须写死）

| 行为 | 规格 |
| --- | --- |
| 首屏渐进渲染 | 先出所有字框（≤800ms），再逐列填字；填充时不做逐字动画，避免闪烁 |
| 点字 | 高亮 60ms 内出现；字卡 180ms 滑入（ease-out）；若该字在下半屏，改从顶部滑入 |
| 连点不同字 | 字卡内容**原地换内容**，不重新播放入场动画（否则会闪） |
| 三视图切换 | 布局尺寸不变，仅替换字形；≤100ms；不做过渡动画 |
| 读音模式切换 | 顶部状态条文案更新 + 字卡重算，无整页刷新 |
| 朗读高亮 | 跟随音频时间轴，允许 ±80ms 误差；不滚动页面（用户自己滚） |
| 放大缩小 | 双指缩放 1×–4×；<0.5× 时只画列框不画字框（降级渲染） |

## 7. 适老化与无障碍

| 项 | 要求 |
| --- | --- |
| 触控目标 | ≥ 48dp（字框视觉 24dp，命中区按最近中心算法扩展） |
| 字号 | 支持系统 200%，正文基准 13sp 起（比常规 App 大 1sp） |
| 对比度 | 正文 ≥ 4.5:1；字框线可以低对比（它是辅助信息） |
| TalkBack | 字卡可完整朗读："般，旧读 bō，今读 bān"；原文区提供"文本视图"作为无障碍替代入口（自绘的字框无法被逐字聚焦） |
| 动效 | 尊重系统"移除动画"设置，全部降级为淡入淡出 |

## 8. Figma 工作流

### 8.1 结构与命名

- 组件名与 Compose 组件 **1:1 对应**：`CharFrame`、`CharCard`、`ModeChip`、`ScriptureBanner`、`ReaderToolbar`
- 用 **Variants** 表达状态，不用分散的图层：`CharCard / state=collapsed|expanded|multi-reading|no-audio`
- 页面文件只放 5 个主屏 + 1 个组件库页，不要按"每个状态一个画板"铺开（会失控）

### 8.2 设计变量 → 代码

1. Figma 原生 **Variables** 定义色板、间距、字号阶梯
2. 导出为 JSON，映射到 Compose 的 `MaterialTheme` + `Dimens`（不要手抄数值，会漂）
3. Dev Mode 交付时开发直接读变量，不读十六进制

### 8.3 交付物（缺一不可）

| 交付物 | 作用 |
| --- | --- |
| 5 个主屏高保真 | 定长相 |
| 组件库（含 Variants） | 定状态 |
| 一页「动态行为规格」 | 定手感（从 §6 复制） |
| 一页「状态矩阵」 | 定边界（空/失败/加载/无音） |
| Prototype 三条链路 | 点字出卡、切三视图、朗读跟随 |

**只给静态图 = 开发一定会做错浮层避让和高亮跟随。** 这三条链路必须有可点的原型。

### 8.4 建议顺序（别一上来做高保真）

| 步 | 产出 | 为什么 |
| --- | --- | --- |
| 1 | 灰度线框（5 屏） | 先定布局与信息层级 |
| 2 | 真机验证（Figma Mirror） | 检查字框可点性、字号可读性 |
| 3 | 5 人可用性测试（含 2 位中老年） | 这是 R5 风险，早测早改 |
| 4 | 高保真 + 组件库 | 布局定了再上色 |
| 5 | Prototype | 交付演示 |

## 10. 待确认

- **Q-1**：「疑似经文」状态条是否展示（目前设计为展示，浅色克制）？会影响结果页视觉密度。
- **Q-2**：字卡是否需要"释义"区？若做，字卡高度要从 35% 提到 45%，会挤压原文区。
- **Q-3**：生字本卡片是否保留原图裁剪（我建议保留，但会增加存储与渲染成本）。
- **Q-4**：是否要暗色模式？若不做，可省 1 人周 UI 与适配工作。
