# 1. 需求

## 1.1 问题陈述

用户面对繁简古籍（典型为佛道经书）时有三层障碍，且现有方案逐层失效：

| 障碍 | 具体表现 | 现有方案为何失效 |
| --- | --- | --- |
| 读不准 | 「般若」bān ruò / 「南无」nán wú / 「祇树给孤独」qí jǐ | 字典与 TTS 只给现代音，不知道旧读 |
| 不认识 | 耨、槃、祇、伽、苾蒭、唵、吽 等超出 3500 常用字 | 手写输入打不出，部首检字对生僻字无效 |
| 切不开 | 竖排右起 + 正文大字与双行小字夹注混排 | 整行 OCR 把正文注文搅在一起，字级框消失 |

三者的共同点是：**现有工具都工作在"行/段"粒度，而用户真正需要的是"字"粒度**。这是本产品的立足点。

## 1.2 目标用户

| 用户 | 典型场景 | 诉求强度 | 对准确率的容忍度 |
| --- | --- | --- | --- |
| 佛道信众 / 居士（主） | 早晚课、共修、自诵 | 极强 | 低：读错即失信 |
| 佛学院 / 道教学院学生 | 读刻本、注疏本 | 强 | 中：可自行校对 |
| 古籍研读者 | 影印本、旧报刊 | 中 | 中 |
| 传统文化爱好者 / 游客 | 寺庙赠阅本、匾额楹联 | 弱 | 高 |
| 港澳台及海外华语用户 | 繁体日常阅读 | 中 | 中：需注音 |

> **判断**：主力用户对"读错"的容忍度极低，对"读得没特色"的容忍度很高。这直接决定了 §4 的 B-01、B-02 两条红线。

## 2.7 关键流程

**主流程**

```
首页「拍照识字」/「相册」
   → 相机页（取景提示、模式：自动/简体/繁体刻本/手写）
   → 处理中（先出字框 ≤800ms，再逐列填字，可取消）
        ├ 无文字：重拍 / 手动框选 / 换模式
        └ 整体置信度低：照常出结果 + 顶部黄条"把握不大，请核对"
   → 结果页（原图+逐字框；正文与注文分层；顶部：三视图 + 旧读/现代音）
   → 点字 → 高亮 + 发音 + 字卡
```

**词组联动（解决 R-04）**

```
点「般」→ 取同列相邻 2–4 字 → 命中「般若」
        → 播 bō rě，字卡标注语境依据
        → 未命中 → 单字主音（旧读优先）+ 列出其余读音
```

**发音降级**

```
点击 → 缓存命中 → 播
     → 未命中 → 合成/取包
          ├ 成功 → 播 + 写缓存
          ├ 缺繁体语音 → 引导装语音包 / 切内置包
          └ 该字无音 → 显示拼音注音 + "暂无语音" + 上报
```

| 指标 | 门槛 | 条件 |
| --- | --- | --- |
| 单字检测召回 | ≥ 96% | 清晰刻本/排印本，正拍 |
| 框贴合 | 框内字面积 ≥ 85%，重叠 ≤ 5% | — |
| 简体印刷 | ≥ 98% 字级 | 正常光照 |
| 繁体刻本 | ≥ 96% 字级 | 含异体字 |
| 繁体排印 | ≥ 98% 字级 | — |
| 手写楷书 | ≥ 85% 字级 | 非连笔 |
| 生僻字识别（超常用 3500） | ≥ 92% | 单独字表评估 |
| 端到端 | ≤ 2.0s | 单页，中端机 |
| 首屏出框 | ≤ 800ms | 渐进式渲染 |

**版式先验（实现要求，非可选优化）**：刻本有界栏线与固定格律（如每半页 10 行 × 20 字），必须先检测界栏线切列再做字级切分；固定行字数可作强约束纠正漏检/多检。这是本场景识别率的主要来源，不得用通用 OCR 直接替代。

## 2.9 读音机制

**前提事实**：旧读与现代音的差异是稀疏的。多数汉字两者一致（山、水、佛、經），仅两类需判别：

- **多音字**：般 / 供 / 刹 / 给 / 叶
- **音译词**：般若、南无、僧伽、瑜伽

因此工作量不在"每字两套音"，而在维护一份 **500–1500 条**的差异集。

**判定优先级（命中即停）**

```
① 语境命中：相邻 2–4 字匹配差异集词条 → 词条读音
② 单字命中：该字在差异集中 → 旧读
③ 均未命中 → 现代读音（不猜、不推断、不硬套）
```

**字表分层覆盖（替代"限定经目"）**

| 层 | 范围 | 数量级 | 语音来源 | 目标字次覆盖率 |
| --- | --- | --- | --- | --- |
| L1 | 通用常用字 + 古籍高频字（耨 槃 祇 伽 迦 毗 唵 吽 苾 蒭…） | 3500–5000 | 人工录音，逐字审定 | ≥ 98% |
| L2 | CJK 扩展 A/B 古籍用字 | 3000–5000 | TTS 合成 + 抽检；差异条目人工录 | 累计 ≥ 99.5% |
| L3 | 其余 CJK 全集 | 数万 | 系统 TTS，失败则提示无音 | 兜底 |

**差异集初始种子（须专家审定后才可上线）**

| 词 | 今读（易错） | 旧读 | 依据 |
| --- | --- | --- | --- |
| 般若 | bān ruò | **bō rě** | 梵 prajñā |
| 南无 | nán wú | **ná mó** | 梵 namas |
| 祇树给孤独园 | zhǐ shù gěi… | **qí shù jǐ gū dú yuán** | 祇 qí、给 jǐ |
| 僧伽 / 瑜伽 | jiā | **qié** | 梵 saṃgha / yoga |
| 摩诃 | kē | **hē** | 梵 mahā |
| 兰若 | lán ruò | **lán rě** | 梵 araṇya |
| 刹那 / 刹土 | shā | **chà** | — |

| 阶段 | 目标 | 交付物 | 出口标准（未达标不进下一阶段） |
| --- | --- | --- | --- |
| M0 立项确认 | 把不确定项锁死 | 本规格 v1.1、合规初判意见 | 决策清单全绿；L1 字表语料方案确定；审定人到位 |
| M1 技术验证 | 证明"能切、能认、能读" | 可跑 Demo、识别率基线报告 | 30 页真实样张字次正确率 ≥ 90%（内部门槛，低于发布门槛）；点字发音跑通 |
| M2 读音资产 | 把"读得对"做成资产 | 差异集 v1（Top 500 审定）、L1 音频包 v1、评测集 100 页 | 差异集审定 100% 有据可查；L1 音频覆盖字次 ≥ 98% |
| M3 MVP | P0 全通 | 内测包 | P0 条目 100% 通过验收；50 人内测无阻断级问题 |
| M4 增强 | P1 补齐 | 公测包 | P1 条目 ≥ 80% 通过；崩溃率 < 0.1% |

## 3.2 关键路径

```
M0 ──┬─→ M1 技术验证（识别线） ──┐
     └─→ M2 读音资产（内容线） ──┴─→ M3 MVP → M4
```

- **两条线必须并行**。M2（审定 + 录音）周期长于 M1，若串行会直接拖死整体。
- **M3 的唯一阻塞项是 M2**：识别可以先做 Demo，但没有审定过的读音不能发版。
- M1 与 M2 的评测样张应复用同一批，避免两套标准。

## 3.3 资产建设（真正的长周期项）

| 资产 | 内容 | 体量 | 责任角色 | 前置依赖 |
| --- | --- | --- | --- | --- |
| L1 字表 | 按语料字频统计 + 人工补古籍高频字 | 3500–5000 字 | 技术 + 领域顾问 | 语料授权 |
| 读音差异集 | 多音字 + 音译词条目，逐条给出处 | 500–1500 条 | 审定人（必需） | 顾问到位 |
| 单字音频包 | L1 逐字录音、响度统一、切片 | 3500–5000 条 | 录音 + 审定复核 | 字表定稿 |
| 评测样张集 | 真实书页拍摄 + 人工标注（字框/正字/读音） | ≥ 100 页 | 标注人力 | 采集设备与场地 |
| 异体字映射 | 经书常见俗写 → 正字 | ≥ 500 组 | 技术 + 顾问 | 字表 |

# 4. 边界要求

## 4.1 范围边界

| 在范围内（v1） | 不在范围内（明确不做） |
| --- | --- |
| 简体印刷、繁体印刷/刻本、手写楷书 | 行草、篆书、金文、甲骨文 |
| 竖排右起、双行小字夹注 | 道教符箓云篆、佛教悉昙/兰札梵字 |
| 单字点读、词组联动、朗读 | 整段翻译、白话讲解、法师开示 |
| 简繁异体互看 | 经文库、按卷检索、共修社区 |
| 生字本、历史、导出 | iOS / Web / 桌面端 |
| 离线识别与 L1 发音 | 云端账号与跨设备同步（v1 不做） |

## 4.2 产品行为红线（不可协商）

| 编号 | 红线 | 说明 |
| --- | --- | --- |
| B-01 | **不猜读音** | 差异集未命中的多音字，不得用模型推测。宁可给现代音。 |
| B-02 | **不隐藏读音** | 任何情况下不得只给一个读音而不提示其他读音存在。 |
| B-03 | **不改原文** | 识别结果必须可与原图字形对照；禁止静默做简繁替换。 |
| B-04 | **不静默失败** | 无音频、无网络、无权限、无识别结果，都必须明确提示并给出下一步。 |
| B-05 | **不预置经文** | 不内置经文全文、不做经文库、不提供讲经/开示内容。 |
| B-06 | **不承诺全对** | 结果页必须可查看置信度或质量告警，不得把不确定包装成确定。 |
| B-07 | **不上传未授权图片** | 默认本机处理；上传需明示 + 二次确认。 |
| B-08 | **不覆盖用户纠错** | 用户手动改过的字与读音，系统不得回滚。 |

> 违反 B-01 / B-03 的功能即使能提升体验指标，也不得实现。

## 4.3 质量边界（下限，非目标）

| 维度 | 下限 |
| --- | --- |
| 冷启动 | ≤ 2s |
| 单页识别 | ≤ 2.0s（中端机） |
| 首屏出框 | ≤ 800ms |
| 点击出声 | P50 ≤ 150ms |
| 内存峰值 | ≤ 400MB |
| 崩溃率 | < 0.1% |
| 首装体积 | ≤ 60MB |
| 单资源包 | ≤ 100MB |

## 4.4 技术边界

| 项 | 边界 |
| --- | --- |
| 平台 | Android only；minSdk 26（8.0）；targetSdk 跟随最新 |
| 离线 | 识别 + L1 发音**必须**离线可用；云能力只能做增强，不能做前提 |
| 模型来源 | 端侧：PaddleOCR 中文繁体微调、ML Kit 中文识别；不得以单一商业 OCR API 作为主路径 |
| 图像 | 单图 ≤ 30MP；超限先下采样 |
| 语音 | Android TextToSpeech 仅作兜底；主路径为内置音频包 |
| 更新 | 字表、差异集、音频包必须可热更新，不随发版 |

## 4.5 数据与合规边界

| 项 | 边界 |
| --- | --- |
| 隐私 | 图片默认不出设备；纠错回传仅含脱敏「字+读音」对，不含图片与上下文文本 |
| 版权 | 影印本/排印本扫描图像多有版权，图像层须自建或使用明确开放许可来源；辞典释义不得直接摘录未授权内容 |
| 宗教定位 | 不预置经文、不做讲经、不做共修、不做捐赠；对外文案不出现宗教机构名 |
| 许可风险 | 若被认定为"互联网宗教信息服务"，大陆上架可能需相应许可；上架前必须取得法务书面意见 |
| 未成年人 | 若面向少儿推广，需符合未成年人内容规范，不采集个人信息 |

## 4.6 变更边界（触发重新评审）

出现以下任一情况，本规格作废重审，不在原计划内消化：

- 要求识别古文字、梵字、云篆；
- 要求预置经文或提供经义讲解；
- 要求增加方言读音体系（粤/闽南等）作为 P0；
- 要求做用户间分享 / 社区（UGC 传播）；
- 上架地区或合规路径变化；
- 审定人无法到位且不接受缩减读音范围。
