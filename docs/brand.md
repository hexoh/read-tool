## 1. 一句话

**一枚靛青的字印：靛青布面，纸白宋体一个「字」。**

设计上不画相机、不画书本、不画取景框——那些在 48dp 上是糊的。只做两件最确定的事：
颜色用产品自己的靛青，字用产品唯一的主角。

## 2. 为什么是这个

| 决策 | 理由 |
| --- | --- |
| 用一个汉字做主体 | 主力用户（中老年、信众）在桌面上找 App，靠的是「认得出那个字」，不是读英文名、也不是看懂图形隐喻。图标本身就是 App 名。 |
| 用宋体而不是黑体 / 圆体 | 宋体的横细竖粗、三角收笔，正是刻本与书页的字形语言；黑体偏界面，圆体偏儿童。这个 App 面向的是「读旧书」，宋体对味。 |
| 靛青底 + 纸白字 | 靛青是选中的语义色（`#185FA5`），也是布面书封的颜色。纸白 `#F6F1E4` 不是纯白，与 App 内纸色同源。反过来（纸底靛字）在浅色桌面上会糊，只留作文档用。 |
| **不做**四角取景框 | 试过：框线与被框住的字在小尺寸下挤在一起，48dp 时框和笔画互相干扰（见 §7 否决稿）。取景框的语言留在 App 内部的相机页与结果页，不必压到图标上。 |
| 不含任何经文、宗教符号 | 产品红线 B-01：应用不提供、不内置经文。图标只用一个通用汉字，不引入任何宗教视觉符号。 |

## 3. 几何

画布 108×108，与 Android 自适应图标同网格（安全区为居中 66dp 圆，内容可延伸至 72dp 被 mask 裁切）。

| 项 | 值 | 说明 |
| --- | --- | --- |
| 画布 | 108 × 108 | 自适应图标标准网格 |
| 字形 | 宋体 Bold，font-size 56 | 约画布的 51.8% |
| 墨迹范围 | 52.2 × 53.8 dp | 实测值；圆形 mask 下「宀」两端仍有余量 |
| 字形中心 | x 54.25 / y 50.50 | 按墨迹外框（不是字身框）对齐画布中心，肉眼才正 |
| 组合版标记 | 76 / 72dp 载体，圆角 31% | 启动页 84dp；比例不变，只改尺寸 |
| 组合版间距 | 标记 → 标题 24dp；标题 → 短线 14dp；短线 → 副标 14dp | — |

> 「字」的墨迹左右基本对称、上下不等（宀在上、子在下），所以**必须按墨迹外框居中**。
> 按字身框居中会明显偏低 —— 这是中文单字做图标最常见的翻车点。

## 6. 用法规则

**可以**

- 桌面图标、商店图标、启动页、关于页、README / 文档页眉
- 单色反白：整版只用一个颜色时，可把底色与字形对调（深底白字 / 浅底深字）
- 最小尺寸 **24dp**；小于 24dp 只保留色块，不放字

**不可以**

- 加描边、投影、渐变、发光、3D 倾斜
- 把字换成其他字、或把「识字」拆开单独使用
- 叠在照片、纹理、经文页面上（会与 App 内的书页照片语义打架）
- 拉伸变形；圆角比例不得改动（固定 31%）
- 用作加载态以外的装饰动画（缩放跳动、旋转）

**清空区**

- 图标：至少留 1/8 画布（13.5dp）
- 组合版：标记与标题的间距不得小于 16dp，四周留白不少于标记高度的 1/2

## 7. 否决稿（留档，避免重复讨论）

| 方案 | 为什么不行 |
| --- | --- |
| 单线条手绘「字」 | 单线重构后像「孑」加一点，认不出是「字」 |
| 四角取景框 + 字 | 48dp 下框线与笔画互相咬合，脏；且暗示「必须框住整页」 |
| 纯纸白底 + 靛青字 | 浅色桌面上几乎看不出边界，白底图标在国产 ROM 上尤其糊 |
| 纯黑底 + 纸白字 | 好看但与品牌色无关，且 App 里没有任何纯黑 |
| 书页折角 / 放大镜 / 相机图形 | 通用隐喻，和一堆阅读类 App 撞脸，且小尺寸下不可辨 |

## 8. 启动页

### 只有一页

Android 12 起**系统启动画面是强制的**，关不掉，只能决定它长什么样。这里的做法是让它「看不见」：
`windowSplashScreenAnimatedIcon` 设为透明，只留纸色底（与 `windowBackground`、与 Compose 启动页同色）。
于是真正的启动页只有 `ui/Splash.kt` 这一页，不会出现「同一个标记先大后小跳一次」。

| 阶段 | 画面 | 实现 |
| --- | --- | --- |
| 系统 splash（首帧之前） | **一屏纯纸色**，无图标无文字 | `values-v31/themes.xml`：图标透明 + 纸色底 |
| 载入期间（约 0.5–2s） | 标记 + 识字 + 短线 + 「拍照 · 点字 · 听读音」+ 底部进度 | `ui/Splash.kt` |
| 载入完成 | 260ms 交叉淡出到首页 | `MainActivity` 的 `Crossfade` |

- **代价**：冷启动很慢的机器上，首帧之前会看到一屏空白纸色（这段时间系统还没画完第一帧）。
  这是刻意取舍——宁可空，也不要同一个标记跳一次大小。
- **不做假延迟**：字库 + 发音包约 20MB，载完就进；慢机器多停一会儿是应该的。
- **不做整页淡入**：从 alpha 0 淡入会先闪一屏更白的空白。
- API 26–30 没有系统启动画面，直接是 `windowBackground` 纸色 → Compose 启动页，同样只有一页。
- 为了让这一页尽早出现：`Store` 的构造（解析设置 / 纠错 / 生字本 / 历史四份 JSON）从 `onCreate`
  挪进了后台协程，不再挡在首帧前面。
- 无障碍：标记里的「字」按 dp 折算成 sp（除以 fontScale），系统字号调到 200% 也不会撑出色块；
  标题与副标正常跟随系统字号。

重新导出：

```bash
bash design/render-icons.sh     # 需要 rsvg-convert + Songti SC（macOS 自带）
```

> SVG 母版里的「字」是 `<text>`，依赖字体。**已导出的 PNG 全部入库**，正常构建不需要字体；
> 只有在改设计重导出时才需要 Songti SC。换到看不到宋体的机器导出会退化成别的衬线体，别再入库。
